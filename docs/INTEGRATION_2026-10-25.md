# Интеграция новой схемы API, 25.10.2026

База — endpoints, коммит 596878a. Перенесены исправления доступа и S3, публичные модели, проверки API, контракт и актуальные схемы из сегодняшней работы. Код базового архива совпал с endpoints побайтово; изменения коллеги сохранены.

- Сохранены DELETE /delete_material, /delete_assignment, /delete_group, /delete_file.
- Удалён дублирующий GET /get_settings. Чтение профиля — GET /get_user_info с прежним user_id; обновление — PATCH /update_settings, только имя и фамилия. Frontend ещё не реализован, вызовов get_settings в клиенте нет.
- get_submissions по умолчанию возвращает свои сдачи по assignment_id; преподаватель курса выбирает student_id. Командная сдача и оценки доступны активным участникам команды.
- Введены общие проверки доступа, публикации материалов/заданий, персонального назначения и принадлежности курса/команды. Журнал соблюдает те же правила видимости.
- grade_submission принимает только graded, конечный обязательный балл 0…max_score. Для возврата используется return_submission. Повторная сдача draft/returned выставляет submitted на сервере.
- Добавлены file_ids с проверкой владения, готовности и транзакционной привязкой. S3: create_file_upload → загрузка формы в хранилище → complete_file_upload → get_file_download. Старый upload_file регистрирует внешнюю HTTP-ссылку, get_file читает метаданные.
- Данные курса уже включают видимый список материалов. Отдельный get_materials нужен для обновления списка без повторной загрузки курса.
- Dashboard и отдельные publish_* не добавляются. Публикация — PATCH update_material/update_assignment с is_published.
