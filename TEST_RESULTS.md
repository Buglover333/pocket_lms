# Проверка API после объединения CRUD-слоя и выделения роутеров

Дата: 24 октября 2026 года.

Основа: ветка endpoints и коммит 352b8b6 из feature/db-schema-and-crud.
Проверки выполнялись с PostgreSQL 16 в отдельной тестовой базе
pocket_lms_api_test_v2_20261024.

Результат: 16 тестов API и архитектуры прошли; комплексный скрипт CRUD-методов
для десяти сущностей проекта также прошёл.

Проверены:

- Регистрация, хранение хеша пароля, дубликаты почты и конкурентная регистрация.
- Валидация входных данных и общий формат ошибок.
- Вход, токены, доступ только к собственным данным и проверка активного пользователя.
- Форматы ответов курсов, модулей и профиля без секретных полей.
- Активное членство в курсах, роли, команды и отсутствие повторов модулей.
- Сохранение прежнего поведения CRUD-метода get_user_disciplines без active_only.
- Шесть эндпоинтов в отдельных APIRouter и отсутствие SQL/подключений в HTTP-слое.
- POST /app на тестовом HTML-файле без БД; 503 при отсутствии сборки frontend.
- CRUD: пользователи, модули, дисциплины, команды, участники, уроки, задания,
  персональные назначения, сдачи/оценки и файлы.

Команды (TEST_DATABASE_URL указывает только на выделенную тестовую базу):

```sh
PYTHONPATH=src uv run python -m unittest discover -s tests -p 'test_api*.py' -v
uv run python tests/test_crud.py
```

API-проверки остаются на unittest; переход на pytest не требуется для изменения
архитектуры. Starlette выдаёт предупреждение о будущем переходе TestClient с
httpx на httpx2; проверки выполняются успешно.

Настоящий frontend ещё не разработан. HTTP-контракт API_DESCRIPTION.md сохранён;
переименование URL и отказ от query-параметра user_id не входят в эту переработку.
